# Reviewer evaluation

Generated by `labauto eval-reviewer --trials 1 --prompt no_hints --runs runs/eval_reviewer_no_hints`. Every number below comes from the case folders under `runs/eval_reviewer_no_hints/20261111T212128Z`.

All data here are synthetic. A made up yield surface is read by a simulated LC/MS and a simulated 1H NMR, and the faults are injected by those simulators. The true fault log comes from the simulators' own records. No reviewer sees it.

Overwatch prompt: no_hints (`src/labauto/agents/prompts/data_reviewer_no_hints.md`): the default prompt with its fault signatures section removed. The default prompt lists fault signatures that resemble how the hard cases were built. This one keeps the rules, the fault kinds, and the reply format, but describes no signature.

## How to read this

QC rules is fixed code that maps quality flags to verdicts and fault kinds. QC plus statistics is the same code plus two plate statistics: a drift rule (LC/MS below NMR on at least 80% of the conditions with 2 or more wells a side, with a median difference of -3 points or lower) and an impurity rule (a well's NMR singlet above its doublet by at least 1.5 points and by 4 times the plate's own spread of those gaps). Neither uses a model. The rules' constants are fixed in review.py: STATS_MIN_N (2), DRIFT_LOW_SHARE (0.8), DRIFT_MEDIAN_MAX (-3), IMPURITY_FLOOR (1.5), IMPURITY_SPREADS (4). The section Baselines across 10 extra seeds per case shows how both baselines do on seeds the case table never used.

Overwatch alone is the model's own review, with the prompt named above. QC rules or overwatch pools the faults QC rules and the overwatch name. QC plus statistics or overwatch pools the faults QC plus statistics and the overwatch name, so it shows whether the model adds anything on top of the best fixed rules here. When QC plus statistics catch every true fault, QC plus statistics or overwatch cannot catch more, so a model can only show a gain there in well recall. Pooling can only add false alarms, so a model that raises fewer shows it only in Overwatch alone against QC plus statistics. Both prompts name the fault kinds, since a reply must use them. So the no_hints prompt has the fewest hints the reply format allows; it is not free of hints.

The hard cases were built to sit in a gap of the plain QC rules: on their case seeds no flag fires. On the hard cases, QC rules catch 0 of 4 true faults and QC plus statistics catch 4 of 4, so simple statistics close that gap here. So an overwatch that beats QC rules has not yet shown it beats fixed rules; compare it with QC plus statistics too. The constants were set with the hard-case recipes known, so read that column as what simple rules do once someone knows what to look for. Over all cases, QC plus statistics catch 13 of 13 true faults and raise 1 false alarm; QC rules catch 9 of 13 and raise 0. So on these case plates QC plus statistics leave no fault for a model to add; a gain there can only be in well recall or fewer false alarms. On the 120 sweep plates, QC plus statistics catch 124 of 130 true faults and QC rules catch 92 of 130. On the 30 hard sweep plates alone, QC plus statistics catch 34 of 40 true faults and find 79 of 143 of the faulty wells, so on seeds other than the case seeds the fixed rules do leave room for a model. 12 cases with 13 true faults is a small set: one case more or less moves every share by a lot.

Scoring. Entries of the same kind are merged first, so grouping cannot change a score. A true fault is caught when a review names its kind and, for injection_failure or nmr_impurity, at least one of its wells. For those two kinds, each named well the fault log does not list under that kind is one false alarm. A plate-wide kind or other that matches no true fault is one false alarm, however often it is named. lcms_nmr_disagreement is not a false alarm when the plate holds a true fault of any kind.

The overwatch ran 1 time per case; its columns add up over trials. No valid review means no reply passed code's checks in 3 attempts (up to 6 replies, since each attempt may retry once on a reply that is not readable JSON). Such a trial counts as naming no fault, and a person would take over. A trial that ended on an endpoint outage is not scored.

Cases marked (hard) are made to slip past the fixed QC flags on their case seeds.

## Baselines across 10 extra seeds per case

No model runs in this section, so it costs no model calls. Each case above ran on one seed. Here code builds each case again on 10 other seeds (seed k is the case seed x 1000 + k, never the case seed itself) and runs only the two fixed baselines. A seed on which the case's fault did not happen is skipped and the next one is used, up to 5 x 10 seeds per case. Faults caught: true faults caught, of all true faults on the case's plates. Well recall: as in the well table. Plates with a false alarm: plates on which the baseline raised at least one false alarm, of the plates built. Every number comes from the folders under `runs/eval_reviewer_no_hints/20261111T212128Z/baseline_seeds`, which list the seeds used in sweep.json. Raw spectra are not kept there.
