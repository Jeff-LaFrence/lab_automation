# Walkthrough: one request, from text to a protocol a person can approve

This follows the first planner scenario through every layer, using the real
files in [examples/sample_run/](../examples/sample_run/). That folder was
written by `labauto check examples/designs/good_factorial.json`, a hand-written
design with the same grid the planner gives for this request. The excerpts in
sections 4 to 8 are copied from those files.

## 1. The request

`examples/requests/01_simple_factorial.txt`:

> Screen catalyst loading at 1, 2, 4 and 8 mol % against base at 1.0, 1.5 and 2.0 equivalents, with 20% co-solvent, in triplicate.

## 2. The design

The planner's only job is to turn the request into a short design (principle
P1). A live reply for this scenario, from qwen3.8:27b served by Ollama, is
recorded in `examples/recordings/01_simple_factorial.jsonl`. A hand-written
reply from before any model was available is kept in
`examples/scripted/01_simple_factorial.json`. Both give the same grid as the
design file used in the sample run,
[examples/designs/good_factorial.json](../examples/designs/good_factorial.json).
The fields that matter here, from that file:

```json
{
  "grid": {
    "catalyst_mol_pct": [
      1,
      2,
      4,
      8
    ],
    "base_equiv": [
      1.0,
      1.5,
      2.0
    ],
    "cosolvent_pct": [
      20
    ]
  },
  "replicates": 3,
  "include_controls": true
}
```

That is 12 conditions (4 catalyst loadings x 3 base levels x 1 co-solvent
level), 3 replicates, controls on. When the planner writes a design, code fills
in the ids, the layout seed, and who wrote it.

## 3. Design rules

Every value must be an allowed step of its factor, and 12 x 3 = 36 sample wells
must fit in the 92 free wells. They do, so the design passes.

## 4. The plan

`expand` turns factor values into microliters. Catalyst at 1 mol % is 2 uL
(0.5 mol % per uL), and the solvent fills each well to 200 uL. The first rows
of `well_map.csv`:

```
well,role,condition_index,replicate,catalyst_mol_pct,base_equiv,cosolvent_pct,solvent_ul,substrate_ul,cosolvent_ul,base_ul,catalyst_ul,total_ul
A1,negative_control,,1,,,,90,40,40,30,0,200

C1,reference_control,,1,2.0,1.5,20.0,86,40,40,30,4,200
```

A1 and B1 are negative controls (no catalyst). C1 and D1 are reference
controls. Samples start at E1, shuffled with the layout seed, which is 7 in
this design file. `labauto plan` takes the seed from `--seed`, 0 by default, so
a planned run of this request puts other samples in E1 onward.

## 5. The worklist

`schedule` orders the transfers: bulk additions first, reagent by reagent, then
small additions (below 20 uL) with a fresh tip each. The first rows of
`worklist.csv`:

```
step,reagent,source_labware,source_well,dest_labware,dest_well,volume_ul,pipette,tip,dispense
1,solvent,reservoir,A5,plate,A1,90,large,new,above_liquid
2,solvent,reservoir,A5,plate,B1,90,large,keep,above_liquid
3,solvent,reservoir,A5,plate,C1,86,large,keep,above_liquid
4,solvent,reservoir,A5,plate,D1,86,large,keep,above_liquid
5,solvent,reservoir,A5,plate,E1,74,large,keep,above_liquid
```

The workcell rules then add up what every source must give and how many tips
each rack must hold, against what the workcell file says is loaded.

## 6. The protocol

`compile` writes a standalone OT-2 protocol. The start of `protocol.py`:

```python
# Generated by labauto from plan p-example-good-factorial (design d-example-good-factorial). Do not edit by hand.
from opentrons import protocol_api

metadata = {"protocolName": "labauto p-example-good-factorial", "author": "labauto"}
requirements = {"robotType": "OT-2", "apiLevel": "2.20"}


def run(protocol: protocol_api.ProtocolContext):
    tips_300 = protocol.load_labware("opentrons_96_tiprack_300ul", 1)
    tips_20 = protocol.load_labware("opentrons_96_tiprack_20ul", 4)
    plate = protocol.load_labware("corning_96_wellplate_360ul_flat", 2)
    reservoir = protocol.load_labware("nest_12_reservoir_15ml", 3)
    small = protocol.load_instrument("p20_single_gen2", "left", tip_racks=[tips_20])
    large = protocol.load_instrument("p300_single_gen2", "right", tip_racks=[tips_300])

    protocol.comment("solvent: bulk additions, one tip, dispensed from above the liquid")
    large.pick_up_tip()
    large.aspirate(90, reservoir["A5"])
    large.dispense(90, plate["A1"].top(-2))
    large.blow_out(plate["A1"].top(-2))
```

and where the small additions begin:

```python
    protocol.comment("catalyst: small additions, fresh tip per well, dispensed into the liquid")
    small.pick_up_tip()
    small.aspirate(4, reservoir["A2"])
    small.dispense(4, plate["C1"])
    small.drop_tip()
```

The protocol runs in the Opentrons simulator. The first lines of `sim_log.txt`:

```

Aspirating 90.0 uL from A5 of NEST 12 Well Reservoir 15 mL on slot 3 at 92.86 uL/sec
Dispensing 90.0 uL into A1 of Corning 96 Well Plate 360 µL Flat on slot 2 at 92.86 uL/sec
Blowing out into A1 of Corning 96 Well Plate 360 µL Flat on slot 2 at 92.86 uL/sec
Aspirating 90.0 uL from A5 of NEST 12 Well Reservoir 15 mL on slot 3 at 92.86 uL/sec
```

The ledger is read back from the simulator's run log: what was dispensed into
each well, by reagent. The first rows of `ledger.csv`:

```
dest_labware,dest_well,reagent,volume_ul
plate,A1,solvent,90
plate,A1,substrate,40
plate,A1,cosolvent,40
plate,A1,base,30
plate,B1,solvent,90
```

The ledger check compares this with the plan for every well and reagent. A
mismatch would point at a fault in this repository's own compiler.

In a planned run (`labauto plan`), the same sections sit under a header that
lists the request, every change from it the planner declared, its assumptions,
and each attempt. A person then runs `labauto approve <run> --by NAME`, which
writes `approval.json` with the design hash and protocol hash. If either file
changes later, the approval is void.

## Break it yourself

Three small edits, and the error each one produces. The messages below are
copied from real runs of `labauto check`, with the run folder and summary
path left out.

1. In a copy of `examples/designs/good_factorial.json`, change the catalyst
   list to `[1, 2, 4, 8.25]`:

   ```
   CAUGHT at design
     FACTOR_OFF_GRID at grid.catalyst_mol_pct[3]: catalyst_mol_pct=8.25 mol % is inside the range but is not an allowed step (0.5 to 10.0 mol % in steps of 0.5).
       hint: The nearest allowed values are 8.0 and 8.5 mol %.
   ```

2. In a copy of the same file, set `"replicates": 8`:

   ```
   CAUGHT at design
     TOO_MANY_WELLS at conditions x replicates: The design needs 96 sample wells (12 conditions x 8 replicates). 92 sample wells are available with controls on. At most 7 replicates of 12 conditions fit.
       hint: Use 7 replicates, or fewer conditions.
   ```

3. In a copy of `configs/workcell_ot2.json`, set the catalyst inventory to
   `"volume_ul": 250`, then run
   `labauto check examples/designs/good_factorial.json --workcell <your copy>`:

   ```
   CAUGHT at workcell
     SOURCE_SHORT at inventory:catalyst: The design needs 278 uL of catalyst. 225 uL is usable (250 uL loaded, 10% held back as dead volume).
       hint: Use fewer wells or lower catalyst amounts, or ask for more catalyst to be loaded.
   ```
