## How to read this

- One trial per plate. The overwatch reviewed each plate once, so its columns add up over plates. Another run could get other replies on some plates.
- QC rules is fixed code that maps quality flags to verdicts and fault kinds. QC plus statistics adds two plate statistics, a drift rule and an impurity rule, with constants fixed in review.py: STATS_MIN_N (2), DRIFT_LOW_SHARE (0.8), DRIFT_MEDIAN_MAX (-3), IMPURITY_FLOOR (1.5), IMPURITY_SPREADS (4). Those constants were set with the hard-case recipes known, so read that column as what simple rules do once someone knows what to look for.
- Pooling can only add false alarms. A pooled column names every fault the baseline or the overwatch names, so it catches at least what each catches alone, and it has a false alarm on every plate where either has one. A model that raises fewer false alarms shows it only in Overwatch alone against QC plus statistics.
- Scoring is the same as on the reviewer evaluation page. A true fault is caught when a review names its kind and, for injection_failure or nmr_impurity, at least one of its wells. For those two kinds, each named well the fault log does not list under that kind is a false alarm. A plate-wide kind or other that matches no true fault is one false alarm. lcms_nmr_disagreement is not a false alarm on a plate with a true fault.
- No valid review means no reply passed code's checks in 3 attempts (up to 6 replies). Such a plate counts as the overwatch naming no fault, and a person would take over. A plate whose trial ended on an endpoint outage is not scored and is left out of every column; a resumed run tries it again.
